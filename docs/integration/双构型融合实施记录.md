## Ubuntu 20.04 / ROS Noetic / Gazebo 环境验收

先初始化其他子模块并确认工具链：

```bash
cd /path/to/px4
git submodule update --init --recursive
make list_config_targets | grep -E 'fmu-v6c|gazebo-classic_fs_fasmv8_flying_car_quad|gz_fully_actuated'
make px4_sitl_default
make px4_fmu-v6c_default
make px4_fmu-v6c_arm
```

逐个启动仿真，每次使用独立的参数存储：

```bash
make px4_sitl gazebo-classic_fs_fasmv8_flying_car_quad
make px4_sitl gz_fully_actuated_hexa
make px4_sitl gz_fully_actuated_hexa_arm
```

在 PX4 控制台分别核对 `param show SYS_AUTOSTART`、`control_allocator status`、`rover_differential status`、`listener actuator_motors 1`、`listener actuator_servos 1`。飞行汽车在 MC 和 Rover 切换前必须上锁；切换后检查旋翼/车轮互斥输出。6003/6004 不应启动差速驱动或飞行汽车模式切换。6004 还应检查三个 Gazebo 关节随 Servo1–3 命令变化。飞行汽车 ROS 包需在 Noetic catkin 工作区中单独验证。

## 当前验收状态与限制

- 已完成静态核对：三个真机 airframe、两个全驱动 POSIX airframe、Classic 四旋翼模型、Gazebo Sim 六旋翼模型、机械臂 SDF 和 `servo_0..2` 映射均存在。
- 已通过：`FlyingCarMode.hpp` 的主机 C++ 断言检查；Gazebo Classic 叠加脚本运行、SDF/XML 解析；新增/修改集成文件的 `git diff --check`。
- 当前 Windows 环境没有可用的 WSL 发行版、PX4 `make/cmake` 和 ARM 交叉工具链，无法在此处完成三个固件目标、Gazebo 实时仿真或真机验收。原全驱动快照本身包含大量历史空白字符告警，完整合并提交的 `git diff --check` 会报告这些上游文件；新增集成文件已单独检查。
- 6004 新增的机械臂仿真几何是占位尺寸，需根据实物测量修订；真机 HX30HM 驱动来自全驱动源码，需在无桨条件下验证串口、方向、行程和失效保护。
- 切换 80003/6003/6004 必须通过 `SYS_AUTOSTART` 并重启；仅改变 `MAV_TYPE` 不会切换产品构型。飞行汽车构型内部的 `MAV_TYPE` 切换只用于其飞行/地面状态机。
